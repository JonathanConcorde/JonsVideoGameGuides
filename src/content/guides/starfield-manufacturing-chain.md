## The objective

The goal is not to build dozens of independent outposts. It is to create a **network** in which specialized extraction sites feed a smaller number of manufacturing locations, eventually supplying one central hub.

That hub becomes the place where you:

- Collect materials
- Manufacture components
- Gain XP in large batches
- Store high-value resources
- Supply future outpost construction
- Generate saleable inventory

## Step 1 — Build only what the network needs

Before placing an outpost, decide its role.

Every outpost should be one of four types:

1. **Extractor** — gathers one or more important raw resources.
2. **Processor** — turns incoming resources into basic manufactured components.
3. **Transfer hub** — solves cargo-link distance or routing problems.
4. **Central factory** — receives resources and handles advanced manufacturing.

If an outpost has no clear job, do not build it yet.

## Step 2 — Start with common construction resources

Your earliest network should continuously produce materials you repeatedly spend while expanding.

Prioritize resources used in:

- Extractors
- Storage
- Power
- Cargo links
- Fabricators
- Structural components

This prevents each new outpost from turning into a shopping trip.

## Step 3 — Create large storage buffers

Cargo links are easier to manage when production has somewhere to accumulate.

At extraction sites:

**Extractor → local storage → outgoing cargo link**

At the receiving site:

**Incoming cargo link → receiving storage → fabricator or central storage**

Do not route everything directly from extractor to fabricator with no buffer. A storage layer makes shortages and routing problems easier to diagnose.

## Step 4 — Manufacture simple components first

Before building an advanced chain, prove that a basic chain works continuously.

Examples of the right progression logic:

- Raw metal + raw metal → common component
- Common component + second component → advanced component
- Advanced component + additional inputs → high-value manufactured item

The specific recipe matters less than the network discipline: one reliable tier at a time.

## Step 5 — Centralize manual crafting

Even if automated fabricators handle part of the chain, keep a central industrial work area where you can manually manufacture large batches.

This is useful because manual production lets you:

- Convert stockpiled resources into XP on demand
- Clear storage bottlenecks
- Produce exactly the component needed for the next expansion
- Avoid waiting for automation when you need something immediately

## Step 6 — Build the XP loop

The network should work while you are questing.

A strong loop is:

1. Leave the network running.
2. Complete missions/exploration.
3. Return to the manufacturing hub.
4. Sleep/rest if using bonuses available to your character.
5. Pull resources from storage.
6. Manufacture in large batches.
7. Sell or store the output.
8. Refill construction reserves.
9. Go back to questing.

The value comes from production happening while you are doing something else.

## Step 7 — Add cargo links carefully

Do not create a web where every outpost ships to every other outpost.

Prefer a hierarchy:

**Extractor sites → regional processor → central factory**

This makes it far easier to identify the broken link when one resource stops arriving.

## Step 8 — Fix bottlenecks before expanding

If the final manufacturer stops, trace backwards.

Ask:

1. Is the final input storage empty?
2. Is the processor starved?
3. Is the cargo link moving?
4. Is the extractor powered?
5. Is local storage full?
6. Is another recipe consuming the same input?

Solve the bottleneck before adding another production tier.

## Step 9 — Keep the central hub comfortable

The manufacturing hub is a place you will revisit frequently.

Include:

- Industrial workbenches
- Organized storage
- Cargo-link receiving area
- Landing access
- Beds
- Research station
- Easy inventory transfer

Efficiency includes reducing your own walking time.

## Step 10 — Expand toward advanced manufacturing

Only after the simple chain works consistently should you add advanced components.

Each new tier should answer one of these questions:

- Does it significantly improve XP batching?
- Does it create a useful high-value component?
- Does it unlock a resource needed across the network?
- Does it make future construction easier?

If not, the added complexity may not be worth it.

## Long-term rule

The best network is not the theoretical maximum-output network. It is the network you can understand, repair, and expand without rebuilding half of it every time something changes.
